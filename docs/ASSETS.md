# アセット管理

`/settings` と独立した管理者専用の `/assets` コマンドを使います。応答・添付は本人限定です。ボタンとフォームの操作時にも、管理者権限・画面の所有者・対象サーバーを再確認します。

## 登録と差し替え

`/assets upload` の `kind` で「キャラクター」「採掘演出」「Excellent結果」「Great結果」「Good結果」を選び、`file` に画像を添付します。`name` は省略可能で、新規では添付名（拡張子を除く）、差し替えでは現在の登録名を使います。名前は1〜80文字です。

新しいキャラクターでは `dialogue` に最初のセリフ（1〜2000文字）を必ず入力します。既存のキャラクターへのセリフ追加は管理画面から行います。画像を差し替える場合は `target` で既存の登録を名前検索してください。キャラクターIDや既存セリフは維持します。種類が異なる登録への差し替えは拒否します。

画像の条件は次の通りです。容量は10進数で判定します。

| 条件 | 処理 |
| --- | --- |
| 正方形、縦横それぞれ600px以下 | 許可。下限は設けない |
| 正方形でない、または600px超過 | 拒否 |
| 500,000 bytes以下 | 推奨範囲 |
| 500,000 bytes超・1,000,000 bytes未満 | 許可し、推奨容量の警告を表示 |
| 1,000,000 bytes以上 | 添付メタデータ段階と読取後の両方で拒否 |
| 画像として読み取れない | 拒否 |

拡張子の許可リスト、GIFのフレーム数検査、画像の自動変換は行いません。画像の読み取りと寸法確認は最初のフレームで行います。拡張子は運用側で適切なものを使用してください。Discordクライアント側で画像が再保存される場合、判定対象はBotが受け取った画像です。

## 管理画面

`/assets manage` から種類を選び、25件単位でページ送りして登録を選びます。画像のプレビュー、名前変更、表示／非表示、完全削除、キャラのセリフ管理ができます。編集後は「一覧を更新」で最新状態を取得してください。無操作5分で終了します。期限が切れた場合はコマンドから開き直します。

非表示の画像・キャラ・セリフは抽選に入りません。再表示すれば再び抽選対象になります。有効なセリフ1件につき抽選候補1件という従来の重み付けを維持します。期間切り替え時には、他の候補があれば直前のキャラを除いて抽選します。各画像種類とセリフ付きキャラを最低1件ずつ残す制約があります。

完全削除は確認画面の「完全削除する（復元不可）」で確定します。キャラを完全削除すると所属するセリフもDBから削除します。操作履歴には本文・画像・名前を複製せず、対象ID・実行者・操作種別・時刻だけを記録します。既存のDiscord投稿や以前に作成されたバックアップは削除しません。並行編集で古くなった画面の操作は拒否するため、一覧を更新してください。

採掘パネルで選択されているキャラの名前・画像・セリフを変更すると、通常5秒以内に同じ投稿を編集します。対象を非表示・削除した場合は有効な候補へ切り替えます。これによる採掘権のリセットはありません。採掘途中の画像を変更・削除しても、その採掘は開始時の画像を表示し、Excellent通知にも同じ画像を使います。

## 初回取り込み

`ASSET_DATA_DIR`（既定 `asset-data`）の `catalog.db` と `media/` を永続保存します。初回のみ `consts/characters.py`、`assets_character/<id>.png`、既存 `assets/` の mining・Excellent・Great・Good画像を取り込みます。元ファイルは変換・圧縮・削除しません。条件を満たさない画像は登録せず、管理画面の「取り込み対象外の一覧」から理由をテキストファイルで確認できます。キャラ画像が無効な場合はそのキャラとセリフを取り込みません。

取り込みは一度だけです。以後のコード更新・再起動で編集内容が上書きされたり、削除した項目が復活したりすることはありません。元ソースへの編集はDBに反映されないので、導入後はBotから編集してください。DBを削除しての再取り込みは運用データを失うため、通常の更新方法には使いません。

## バックアップと復元

起動時と24時間ごとのバックアップで、ウォレットDBとは別に `assets_*.zip` を作成します。ZIPにはSQLiteスナップショットと、そのDBが参照する画像（非表示分も含む）をまとめます。既定の保持は10日・各系列10件です。完全削除後の過去のバックアップには削除前の内容が残る場合があります。

復元時はBotとwatchdogを止め、現在の保存先を退避し、信頼できるアセットZIPを空の保存先へ展開してください。`catalog.db` と `media/` をセットで復元し、そのディレクトリを `ASSET_DATA_DIR` に指定して起動します。DBだけ／画像だけの復元は避けてください。テスト環境では本番と保存先を分離します。公開Gitには運用DB・画像保存先・バックアップを追加しません。

ファイルシステムのロックで不要画像を削除できなかった場合は警告ログを残します。DBの削除は完了しており、その画像は抽選・プレビュー・新規バックアップから除外されます。常設パネルの保持には `SETTINGS_FILE` も必要なので別途保全してください。

## 表示速度

Bot側で採掘開始時に画像を読み込み、同じ採掘内で使い回します。これは途中編集への耐性を持たせる処理です。利用者端末へのDiscord画像配信をBot側キャッシュだけで短縮する保証はありません。小さい画像を登録する運用を推奨します。ログの `Mining animation upload` と `Mining result upload` はDiscordへのアップロード時間で、演出用の3秒待機と利用者側の描画時間を含みません。
