## DB構造と旧DBの引き継ぎ

全DBを作り直す必要はなく、既存 `USERS` の残高・生涯採掘量・採掘回数・Excellent回数を維持する追加移行とした。

| テーブル | 扱い |
| --- | --- |
| USERS | 既存カラム・個人データを保持。useridに一意インデックス追加 |
| CLAIMS | 新規。個人ごとのリセット期間と消費回数 |
| LEDGER | 新規。操作ID、実行者、送金元/先、金額、種別、日時 |
| WALLET_META | 新規。旧採掘権の移行済み状態を記録 |
| 旧MINING | 現期間の個人採掘済みを一度だけ読み取り移行。以降は使用せず、元DBを保管 |

起動時にSQLiteバックアップを作成してから移行する。現期間の旧個人採掘済みを引き継ぎ、切り替え直後の二重受け取りを防ぐ。旧国別フラグは採掘制限に使わない。国集計用のUSERS ID 1〜4はランキングから除外し、履歴を壊さないよう自動削除しない。

ローカル旧DBのコピーでは、既存9行の全カラムを維持したまま移行を2回実施済み。重複userid等がある場合は自動削除や推測による統合をせず停止する。不要な旧MINING DBや国集計行を整理する場合は、移行確認・退避後の別作業として扱える。初期化して個人残高まで失わせる運用は採用していない。切り戻しはコード・DB・設定をセットで復元し、新規取引が発生済みならLEDGERを先に退避する。
