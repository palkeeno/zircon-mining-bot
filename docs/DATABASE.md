# 新規wallet DB仕様

旧DBからの引き継ぎを行わず、新しいSQLiteファイルから開始する。`DB_WALLET` に保存先を指定する。旧 `DB_USERS` / `DB_MINING` は参照しない。旧DBや環境設定を自動削除・上書きしない。

## 管理者による全初期化

`/wipewallet` はCLOSE中、2段階の確認後に実行する。`BEGIN IMMEDIATE` で書き込みを直列化し、別の読み取り接続から削除直前のコミット済みDBをバックアップする。バックアップの整合性と保存成功を確認した後、同じ書き込みトランザクションで `wallet_ledger` / `mining_claims` / `mining_resets` / `wallets` を削除し、`mining_state.manual_period` をNULLへ戻す。スキーマ・バージョン・singleton行は維持し、SQL失敗時は全削除をロールバックする。

バックアップ名は `wallet-wipe-日時-操作ID.db`。通常のバックアップの期限・個数整理と区別して自動削除せず保持する。設定JSON・アセットDB・画像は触らない。初期化の監査ログはBotの管理者ログに記録し、新しく空にしたDBには履歴行を追加しない。削除前の操作IDも消えるため、採掘を閉じて進行中の操作が終わってから実行する。以後は新規ユーザーとして残高・実績を作成する。

## テーブル

| テーブル | 用途 |
| --- | --- |
| `wallets` | Discordユーザーごとの残高と採掘実績 |
| `mining_claims` | ユーザーごとに最後に使用した採掘期間・回数 |
| `wallet_ledger` | 採掘・付与・引き去り・転送・寄付の操作履歴 |
| `mining_state` | 現在の手動リセット期間。id=1の単一行 |
| `mining_resets` | 手動リセットの操作ID・実行者・期間・実行日時 |

`wallets` のカラムは次のとおり。

| カラム | 意味 |
| --- | --- |
| `user_id` | DiscordユーザーID。主キー。旧連番idと国集計用ユーザーはない |
| `balance` | 現在の保有数 |
| `total_mined` | 採掘による累計獲得量。管理者付与は含めず、寄付・転送・引き去りでも減らない |
| `mining_count` | 累計採掘回数 |
| `excellent_count` | 累計Excellent回数 |
| `updated_at` | 最後に残高が変わった日時。操作履歴と同一の日本時間ISO 8601形式 |

数値は整数・非負・NOT NULL、初期値0。Excellent回数は採掘回数以下。SQLiteの整数範囲を超える加算は拒否し、トランザクション全体をロールバックする。`total_mined` は将来の表示・集計用に保存し、今回のUIへ新たなランキング等は追加しない。

履歴には `request_id`、`actor_id`、`source_id`、`target_id`、`amount`、`kind`、`created_at` を保存する。数量は正の整数、種類は5種に限定し、種類と転送元・先の組み合わせもDBで検証する。採掘権・履歴の対象アカウントには外部キーを設定し、書き込み接続で `foreign_keys=ON` にする。実行者は残高を持たない管理者もあり得るため、actor_idにwalletsへの外部キーは付けない。

残高・採掘権・履歴の更新は `BEGIN IMMEDIATE` の同じトランザクションで行う。Discord操作IDの重複を拒否する。現在残高と累計採掘量は増減要因が異なるため、一方から他方を計算しない。

## 初期化・バージョン

`models/wallet_schema.py` がスキーマ作成を担当し、`models/wallet.py` が通常のデータ更新を担当する。スキーマバージョンは `PRAGMA user_version=1`。

- 空のDB（version=0かつユーザーテーブルなし）：1つのトランザクションでスキーマを作成する。
- 対応バージョンのDB：既存データを保持し、作り直さない。
- 既存の未バージョン管理DB・未対応バージョン：エラーで停止し、削除・推測変換しない。

将来バージョンを追加する際は、既存バージョンからの明示的なスキーマ更新を追加して検証する。今回の「旧イベントDBは引き継がない」という方針は、今後のバージョン更新でデータを初期化してよいという意味ではない。現時点で未対応バージョンの変換処理は持たない。

## バックアップとCSV

SQLite backup APIで `DB_WALLET` のみを保存する。期限・個数による整理はそのDB名のバックアップだけを対象にし、旧DBや無関係なファイルは対象外。

`/exportwallet` は日本語の複数選択メニューを維持する。選択したテーブルと同名のCSVを出力する（例：`wallets.csv`、`mining_state.csv`）。「移行・リセットの管理情報」は「採掘リセットの現在状態」に変更した。CSVは1つの読み取りスナップショットから生成し、Discord IDは文字列として取り込む。自動復元機能はない。
