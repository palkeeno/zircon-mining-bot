# Zircon Mining Bot 管理者マニュアル

## 管理画面

`/settings` をAdministrator権限で実行します。応答は本人のみ表示されます。

設定画面は無操作5分、対象選択とランキングは無操作3分で期限切れになります。応答しなくなった場合は `/settings` または常設のランキングボタンから開き直してください。

- **OPEN / CLOSE**：採掘を開閉する。保有数確認・寄付は閉鎖中も利用可能。
- **リセット時刻・回数**：時（0〜23）、分（0〜59）をそれぞれカンマ区切りで設定。組み合わせ数が1日のリセット回数。期間内の採掘回数は1〜100。
- **ロール・通知先**：採掘可能ロールと未所属者Excellent通知先を選択。通知先はBotの閲覧・送信・添付・埋め込み権限も確認する。
- **国別Excellent通知先**：Brave / Freedom / Glory / Peacefulそれぞれのテキストチャンネルを選択する。Botの閲覧・送信・添付・埋め込み権限が必要。設定一覧に4か国の現在の通知先を表示し、保存した国だけ直ちに変更する。再起動後も保持し、未所属者の通知先・国庫・採掘投稿先には影響しない。
- **4か国の国庫**：Brave / Freedom / Glory / Peacefulの国ロールに対応する国庫アカウントをそれぞれ選択。同一アカウントの重複登録は拒否。保存後は同じ画面の設定一覧を更新する。
- **確率・獲得数**：Excellent・Greatの百分率とExcellent / Great / Goodの獲得数。Good確率は残り。共通確率とロール別確率の合計は各100%以内。
- **ロール別確率の変更／確認**：既存のロール名ベースの優先設定を引き継ぐ。小さい優先順位を先に適用。確率欄を両方空欄にすると該当ロールの設定を削除。
- **常設投稿を確認・復旧**：既存の2投稿を更新し、削除されたものだけ再作成。
- **現在の設定を更新表示**：別フォームで変更した後に最新情報を表示。

付与 `/add`、引き去り `/remove`、管理者転送 `/transfer` は独立したコマンドです。数量は1〜1,000,000,000。引き去りや転送でマイナス残高にはできません。一般ユーザーの `/donate` は所属国の国庫へ自動転送します。未所属・複数国所属・所属国の国庫が `0`・複数国で同じ国庫が設定された場合は拒否します。国庫の変更は以後の寄付先を変更するだけで、旧国庫の残高は移動しません。残高を移す場合は管理者が `/transfer` を使います。

各国の初期値は `BRAVE_TREASURY_USER_ID` などの環境変数で設定できます。画面で保存した `treasury_user_ids` の値を優先し、キーは `1=Brave / 2=Freedom / 3=Glory / 4=Peaceful` です。旧単一国庫の `TREASURY_USER_ID` / `treasury_user_id` は使用しません。所属国を推測して割り当てず、旧国庫のアカウント・残高を保持して4か国の設定を明示的に行ってください。国庫設定だけの変更でDBの再構築・残高移行は不要です。

国別通知先の未設定時は `.env.production` の `BRAVE_CHAT` / `FREEDOM_CHAT` / `GLORY_CHAT` / `PEACEFUL_CHAT` を使用します。画面から保存した `country_excellent_chats`（キー `1=Brave / 2=Freedom / 3=Glory / 4=Peaceful`）を優先します。同じチャンネルを複数国の通知先に指定することも可能です。保存先は `SETTINGS_FILE` のJSONで、DBの変更は不要です。未所属者の通知先は従来どおり「ロール・通知先」で変更します。

## 即時リセット・CSV取得

`/resetmining` は設定画面と独立した管理者コマンドです。全員の期間内回数をクリアし、採掘パネルのキャラを切り替えます。残高・累計実績・定時スケジュール・OPEN/CLOSEは維持します。次の定時リセットも通常通り発生します。DB更新後にパネル通信だけ失敗した場合は自動再試行するため、キャラ表示のために再度リセットする必要はありません。

`/exportwallet` は管理者本人限定の日本語の複数選択メニューを開きます。次の情報から必要なものを1〜5種類選択し、「選択した情報をダウンロード」を押すと、選択分だけ添付します。選択画面は3分間利用でき、操作のたびに実行者と管理者権限を再確認します。

- `wallets.csv`：残高・累計実績
- `mining_claims.csv`：現在記録されている期間別採掘回数
- `wallet_ledger.csv`：残高操作の履歴
- `mining_state.csv`：現在の手動リセット期間
- `mining_resets.csv`：手動リセットの操作履歴

選択したテーブルはダウンロードボタンを押した後の同じ読み取りスナップショットです。採掘回数の期間更新は採掘時に行うため、未採掘ユーザーのmining_claimsには以前の期間が残ることがあります。UTF-8 BOM付き、ヘッダー付きで、空テーブルも出力します。大きいCSVはZIP化し、上限超過時はエラーを表示します。Excel等ではDiscord IDの列を文字列に指定して読み込みます。CSVは調査用で、自動復元用バックアップの代用ではありません。

## ウォレットの全初期化

`/wipewallet` は設定画面と独立したAdministrator専用コマンドです。残高を残して採掘権だけ回復したい場合は `/resetmining` を使ってください。

1. `/settings` で採掘をCLOSEにし、進行中の採掘や残高操作が完了したことを確認する。
2. `/wipewallet` を実行し、本人限定の「確認1/2」で削除対象を読み、「内容を理解して最終確認へ」を押す。ここまでは初期化しない。
3. 「確認2/2」で **全員のウォレットを初期化する** を手入力して送信する。入力欄は空で始まり、確認文の不一致・キャンセル・期限切れでは初期化しない。

確認は開始から3分で失効します。各操作でコマンドを開いた本人・管理者権限・対象サーバーを確認し、実行直前にもCLOSEを確認します。最終送信は一度だけ処理します。期限切れのフォームでDiscordの一般的なエラーが表示された場合は、閉じてコマンドから開き直してください。

削除するものは、全員（4か国の国庫も含む）の残高・累計獲得量・採掘回数・Excellent実績、残高増減履歴、期間別採掘回数、手動リセット履歴です。手動期間も未設定に戻します。キャラ・画像・セリフ、Bot設定、国庫アカウントの指定、常設投稿は保持します。採掘はCLOSEのままなので、完了を確認してから必要に応じてOPENに戻してください。

削除前にSQLiteの整合したスナップショットを `BACKUP_DIR/wallet-wipe-日時-操作ID.db` に保存します。バックアップ作成・整合性確認・保存に失敗した場合は削除しません。削除中のSQLエラーも全体をロールバックします。バックアップはDiscordには添付せず、完了時にファイル名を表示します。実行者・操作ID・対象アカウント数・バックアップ保存先は管理者ログにも記録します。通信エラーで完了通知を受け取れなかった場合は、再実行する前にログとDBを確認してください。

このバックアップは通常のバックアップ世代整理の対象外で、自動削除しません。残高・履歴・ユーザーIDを含むため管理者だけが読める場所に保管し、不要になったものは運用側で整理してください。DBを利用上の空状態に戻す機能であり、バックアップを含む物理的なデータ抹消ではありません。

復元する場合はBotとwatchdogを停止し、現在の `DB_WALLET` を退避したうえで、信頼できる対象バックアップを `DB_WALLET` の保存先へ復元して再起動します。設定やアセットは復元対象外です。復元時点より後の残高操作は失われるため、バックアップの日時とログを確認してください。

検証範囲は [ウォレット初期化検証記録](TEST_REPORT_WALLET_WIPE_2026-10-26.md) を参照してください。

## 本番への切り替え

1. 本番Botとwatchdogを停止し、二重起動を防ぐ。
2. 旧DB、設定、環境設定を退避する。旧DBは新システムへ取り込まない。
3. レビュー・マージ済みの変更を既存の `/home/zircon-mining` へ配置し、依存を更新する。
4. `.env.production` に `DB_WALLET=/新しい保存先/wallet.db` を設定する。親ディレクトリを用意し、未作成のファイルを指定する。`DB_USERS` / `DB_MINING` は使用しない。
5. `ENV=production`、`CWD`、投稿先権限、Server Members Intentを確認して起動する。新規DBは残高・実績・操作履歴が空で開始する。旧形式のDBを指定した場合はエラーで停止する。既存ファイルを自動削除しない。
6. 常設投稿IDの設定を引き継ぐ場合は既存2投稿を編集する。投稿IDがない場合のみ新規作成する。DBと投稿IDの設定は独立している。
7. `/settings` で4国庫・採掘ロール・開閉・リセット時刻・Excellent通知先を確認する。
8. 残高ゼロからの採掘、管理操作、CSV、再起動後のデータ保持を確認してwatchdogを再開する。

バックアップ対象は `DB_WALLET` と、アセットDB・画像をまとめた `assets_*.zip` です。ウォレットとアセットは別々のスナップショットです。アセットのZIPはDBと参照画像を同じ読み取り期間に取得します。復元時はBotを停止し、ZIP内の `catalog.db` と `media/` を一緒に復元してください。旧DBは読み込み・バックアップ・自動整理の対象にしません。24時間ごとのバックアップはCLOSE中も実行します。SQLiteのbackup APIを使い、起動時バックアップと定期バックアップが同名で上書きされないようマイクロ秒を含むファイル名を使います。

ロールバックはBotを停止し、退避したDB・設定と対応する旧コードをセットで復元します。新バージョンで発生した取引がある場合、復元で失われるためwallet_ledgerを確認して残高の扱いを決めてください。

アセット機能の導入時は、本番専用の `ASSET_DATA_DIR` を設定し、元画像・`consts/characters.py` を残した状態で初回起動してください。取り込み対象外の報告を確認し、必要な画像は条件を満たすものを手動で登録します。以後、ソースの画像やセリフを変更してもDBへ再取り込みしません。操作方法と復元手順は [アセット管理](ASSETS.md)、検証結果は [アセット検証記録](TEST_REPORT_ASSETS_2026-10-24.md) を参照してください。

## Discord実操作チェック

2026-10-22〜23の隔離テスト結果は [実Discord検証記録](TEST_REPORT_2026-10-22.md) を参照してください。

- 指定ロール保持者／未保持者、OPEN／CLOSEで採掘可否を確認。
- 同じ人が国ロールを変えても同期間の追加採掘ができないことを確認。
- リセット時刻をまたぎ、投稿IDが変わらず採掘権だけ更新されることを確認。
- 再起動後も同じ2投稿のボタンが使えることを確認。
- 管理者以外が付与・引き去り・転送・設定を実行できないことを確認。
- 付与→引き去り→管理者転送→寄付を小額で確認し、採掘回数とExcellent回数が増えないことを確認。
- 21人以上のデータで10件／10件／残りのページ送り・戻しを確認。すべて本人限定表示であることを確認。
- 国所属者／未所属者それぞれのExcellent通知と、本人表示の結果画像と通知サムネイルが同じことを確認。
