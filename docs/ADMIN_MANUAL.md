# Zircon Mining Bot 管理者マニュアル

## 管理画面

`/zmsettings` をAdministrator権限で実行します。応答は本人のみ表示されます。

- **OPEN / CLOSE**：採掘を開閉する。保有数確認・寄付は閉鎖中も利用可能。
- **リセット時刻・回数**：時（0〜23）、分（0〜59）をそれぞれカンマ区切りで設定。組み合わせ数が1日のリセット回数。期間内の採掘回数は1〜100。
- **ロール・寄付先・通知先**：サーバー内のロール、国庫アカウント、未所属者Excellent通知先を選択。通知先はBotの閲覧・送信・添付・埋め込み権限も確認する。
- **確率・獲得数**：Excellent・Greatの百分率とExcellent / Great / Goodの獲得数。Good確率は残り。共通確率とロール別確率の合計は各100%以内。
- **ロール別確率の変更／確認**：既存のロール名ベースの優先設定を引き継ぐ。小さい優先順位を先に適用。確率欄を両方空欄にすると該当ロールの設定を削除。
- **常設投稿を確認・復旧**：既存の2投稿を更新し、削除されたものだけ再作成。
- **現在の設定を更新表示**：別フォームで変更した後に最新情報を表示。

付与 `/zmadd`、引き去り `/zmremove`、管理者転送 `/zmtransfer` は独立したコマンドです。数量は1〜1,000,000,000。引き去りや転送でマイナス残高にはできません。一般ユーザーの `/zmdonate` は指定された国庫にのみ送ります。寄付先が `0` の間は操作を拒否します。

## 本番への切り替え

1. 本番の旧Botとwatchdogを停止し、二重起動を防ぐ。
2. `users.db`、`mining.db`、`data/`、環境設定を退避する。移行後の入出金を旧バージョンが扱えないため、切り替え中は旧Botを同時実行しない。
3. レビュー・マージ済みの変更を既存の `/home/zircon-mining` へ配置し、仮想環境の依存を更新する。
4. `ENV=production`、DBパス、`CWD`、投稿先権限、Server Members Intentを確認する。
5. 起動時はSQLiteバックアップ後、USERSを維持して個人採掘権CLAIMS、取引履歴LEDGER、移行管理WALLET_METAを追加する。旧MININGは読み取り専用。現在の期間中の採掘済み記録を個人単位で引き継ぐ。重複USERSなど不整合があれば起動を失敗させ、勝手に削除・統合しない。
6. 初回起動時に2件の常設投稿を作り、IDを `data/user_setting.json` に保存する。以前の投稿は自動削除しない。必要なら管理者が旧投稿を整理する。
7. `/zmsettings` から国庫アカウントを設定し、未所属Excellent通知先を確認する。
8. 下記のDiscord実操作確認を実施後、watchdogを再開する。

24時間ごとのバックアップはCLOSE中も実行します。SQLiteのbackup APIを使い、起動時バックアップと定期バックアップが同名で上書きされないようマイクロ秒を含むファイル名を使います。

ロールバックはBotを停止し、退避したDB・設定と対応する旧コードをセットで復元します。新バージョンで発生した取引がある場合、復元で失われるためLEDGERを確認して残高の扱いを決めてください。

## Discord実操作チェック

- 指定ロール保持者／未保持者、OPEN／CLOSEで採掘可否を確認。
- 同じ人が国ロールを変えても同期間の追加採掘ができないことを確認。
- リセット時刻をまたぎ、投稿IDが変わらず採掘権だけ更新されることを確認。
- 再起動後も同じ2投稿のボタンが使えることを確認。
- 管理者以外が付与・引き去り・転送・設定を実行できないことを確認。
- 付与→引き去り→管理者転送→寄付を小額で確認し、採掘回数とExcellent回数が増えないことを確認。
- 21人以上のデータで10件／10件／残りのページ送り・戻しを確認。すべて本人限定表示であることを確認。
- 国所属者／未所属者それぞれのExcellent通知と、本人表示の結果画像と通知サムネイルが同じことを確認。

## 2026-10-20 の実装時検証

- 本番BotトークンでDiscord APIの本人確認：HTTP 200。
- 採掘チャンネル、4か国のExcellentチャンネルの読み取り：HTTP 200。
- **既存の未所属Excellent通知先：HTTP 403。権限修正または管理画面から通知先変更が必要。**
- 国庫アカウントは未指定のため暫定値0。寄付は設定後に有効。
- ローカルの既存DBをコピーして移行を2回実施し、既存USERS 9件の全カラムが不変、SQLite integrity_checkがokであることを確認。元DBのSHA-256も不変。
- 自動テストはDiscord応答をモックし、実SQLiteで競合・移行・残高を検証。実Discordでの投稿・ボタン操作や本番へのデプロイは実施していない。
